dmm2xm — Python-версия с графическим интерфейсом
=================================================

Что это
-------
Это переписанный на Python (с GUI на tkinter) конвертер dmm2xm.exe
(музыка Doom2D формата DMM <-> FastTracker XM), исходно написанный на
Object Pascal (dmm2xm.dpr, BeRoXM.pas, WadFile.pas, streams.pas,
helpers.inc). Алгоритм конвертации (квантование нот, панорамирование
инструментов, фиксы петель для стоковых сэмплов Doom2D и т.д.)
перенесён построчно, а не просто "обёрнут" вызовом старого exe —
никакой Wine/Pascal не требуется, всё работает на чистом Python.

Помимо прямой конвертации (DMM -> XM) программа умеет обратную:
трекерные модули XM, IT, S3M и MOD -> DMM + файлы инструментов .DMI.
Обратное направление заметно доработано по сравнению с оригиналом
(см. раздел "Исправления и доработки" ниже): тайминг, эффекты, память
каналов, громкость внутри ноты, ограничения игрового движка.

Файлы
-----
  dmm2xm_core.py     - структуры данных и низкоуровневые функции
                        (чтение WAD/DMM/DMI, чтение/запись XM, загрузчики
                        MOD/S3M/IT); здесь же константа DMM_REF_TEMPO
  dmm2xm_convert.py  - сам алгоритм конвертации (прямой и обратный);
                        в начале файла и рядом с функциями лежат
                        настройки (лимиты запекания SHAPED_*,
                        EVENT_MIN_STEP, WAD_MAX_LUMPS и т.п.)
  dmm2xm_gui.py       - графический интерфейс (запускаемый файл)

Запуск
------
    python3 dmm2xm_gui.py

Требуется только Python 3 со стандартной библиотекой (tkinter обычно
идёт в комплекте; в Ubuntu/Debian при необходимости: apt install
python3-tk). Внешние зависимости не нужны.

Интерфейс: 4 вкладки
---------------------
1. "Пакетная конвертация (WAD)" — аналог conv_wad.bat: таблица песен и
   их квантований предзаполнена ровно теми же значениями, что были в
   conv_wad.bat (ALLRIGHT=8, BEST=6, GLAD=8, ... и т.д.), но каждое
   поле можно отредактировать, добавить свою строку, отключить
   отдельные песни галочкой. Указывается путь к doom2d.wad и папка для
   результатов, есть общие опции -r/-m/-b.

2. "Пакетная конвертация (папка .dmm)" — аналог conv_dmm.bat: та же самая
   таблица песен/квантований, но берёт уже распакованные из .wad файлы
   вида "ИмяПесни.dmm" (например, распакованные сторонним инструментом
   вроде QPak) из указанной папки, вместо чтения прямо из .wad. Файлы
   инструментов (.DMI) при этом ищутся рядом с .dmm или в подпапке
   "dmi\", как и в оригинале.

3. "Один файл (DMM/WAD → XM)" — полный аналог командной строки
   dmm2xm.exe для прямой конвертации: -q (квантование), -r (макс.
   строк в паттерне), -o (файл результата), -f (имя песни в WAD),
   -m (моно), -b (эмуляция бага SoundBlaster на 44 кГц).

4. "Обратно (XM → DMM)" — обратная конвертация трекерного модуля
   (.xm, .s3m, .it, .mod) в DMM + отдельные файлы инструментов .DMI
   (кладутся рядом с .dmm). Кроме путей к файлам, здесь четыре настройки;
   при запуске в них уже выбраны рекомендуемые значения:

   а) "Для модулей с >8 каналами" — DMM хранит ровно 8 каналов, значит,
      у модуля с большим числом каналов нужно выбрать 8:
        * первые 8 по номеру (как было в оригинале);
        * 8 самых используемых по количеству нот;
        * 8 самых используемых по суммарной громкости нот
          (рекомендуется, выбрано по умолчанию): канал с редкими, но
          громкими нотами (бас/соло) не проигрывает каналу с частыми
          тихими украшениями. В IT каналы, заглушённые в трекере
          (mute), в выборе не участвуют и не конвертируются.

   б) "Изменение громкости во время ноты (слайды Axy/Dxy, огибающие
      IT/XM)" — у ноты DMM одна громкость, а в трекерах она меняется по
      ходу ноты (затухание хай-хета командой A0F, fade-out, огибающие
      громкости IT и XM — родная огибающая инструмента XM теперь тоже
      разбирается и учитывается, как и IT-шная). Три режима:
        * "Как раньше": слайды игнорируются, огибающие IT запекаются в
          дополнительные инструменты (как в версии до доработок);
        * "События громкости" (рекомендуется, выбрано по умолчанию): игровой
          движок умеет менять громкость уже звучащей ноты особым
          событием "только громкость" (байт ноты 0xFF, так сделаны
          плавные затухания в стоковой песне СОЛО). Слайды и огибающие
          записываются такими событиями прямо в паттерн: новых
          инструментов и .DMI-файлов не появляется, .dmm растёт на 4
          байта за каждое изменение громкости (в формате не больше
          65535 нот на песню);
        * "Запекать слайды и огибающие в инструменты": форма затухания
          рисуется прямо в семпле отдельным инструментом. Для сложных
          форм это точнее, но каждая такая нота — новый ресурс в WAD
          (лимиты запекания: не больше 250 инструментов, не длиннее
          24000 сэмплов на ноту, суммарно не больше 1,2 млн сэмплов;
          сверх лимита нота получает одну усреднённую громкость).
      Установка громкости посреди ноты (Cxx на пустой строке, колонка
      громкости) в режимах "Как раньше" и "События громкости"
      записывается событием 0xFF, а при запекании входит в форму
      запекаемого инструмента.

   в) "Учитывать смещение семпла (Oxx/9xx)" (выключено по умолчанию) —
      трекеры умеют начинать семпл с середины (S3M/IT Oxx, MOD/XM 9xx:
      "нарезка" барабанных лупов), а DMM нет. Для каждой пары
      "инструмент + смещение" создаётся копия инструмента, PCM которой
      начинается с нужного места (смещение внутри петли, до петли и за
      концом семпла учитываются; за концом одноразового семпла нота
      молчит). Копия = лишний .DMI, поэтому на песню создаётся не больше
      32 копий (дальше смещение игнорируется, нота играет с начала;
       об этом пишется в журнал). На тестовых файлах: S3M +3..5
       инструментов, MOD/IT около +20..30 — как и режим "Запекать" из
       предыдущего пункта, это точнее по звучанию, но лишние ресурсы
       для WAD, поэтому по умолчанию выключено. Параметр в коде:
       convert_backward(..., sample_offsets=True).

    г) "Разделить subsongs (Bxx/Cxx)" (выключено по умолчанию) — модули
       с переходами позиции (Bxx в XM/MOD) содержат несколько
       подпесен: интро, луп, скрытые разделы, недостижимые из начала.
       Разбиение повторяет логику самого OpenMPT (проверено
       по openmpt123 --info/--subsong и длительностям с точностью
       до 0,1 с): каждый ордер списка воспроизведения попадает ровно
       в один сабсонг; песня обрывается перед ордером чужой песни,
       на замкнувшемся лупе (он играется один раз) или в конце
       таблицы. Пример — BGM12.XM: 4 файла 6:05 / 0:22 / 4:10 / 0:09
       (ординарный проход даёт 10:44, как сумма у OpenMPT).
       Каждый сабсонг — свой .dmm "<имя>_subN.dmm" с уже развёрнутым
       порядком (переходы середины паттерна укорачивают паттерн,
       прыжок в чужую песню дальше не ведётся), инструменты общие:
       одинаковые по содержимому .DMI переиспользуют один файл,
       так что упаковка всех частей плюс объединение их DMI в один
       WAD дублей не стоит. Замкнувшийся луп превращается в точку
       повтора DMM (байт после 255), песня без лупа — в повтор
       с собственного начала, как и раньше. Если таблица целиком
       образует одну песню, имя файла обычное, без суффикса.
       Без этой галочки (по умолчанию) весь список конвертируется
       в один DMM как есть, а скорости берутся из реальных путей
       проигрывания (см. п. 1 и раздел про Bxx ниже).
       Параметр в коде: convert_backward(..., split_subsongs=True).

Внизу — общий журнал, в который выводятся те же сообщения
(предупреждения о рассинхронизации нот, потерянных тиках и т.п.),
что печатала консольная версия, а также новые сообщения обратной
конвертации (см. раздел "Сообщения журнала").

Известные ограничения этого Python-порта (по сравнению с оригиналом)
---------------------------------------------------------------------
* Поддерживаются ВСЕ версии формата XM, которые поддерживал оригинал:
  и "современные" (version > 0x0103 — FastTracker II, OpenMPT,
  MilkyTracker, Schism Tracker и т.п.), и старые (version <= 0x0103),
  у которых другой (более компактный) заголовок паттерна и данные всех
  сэмплов идут одним блоком после паттернов, а не сразу за каждым
  инструментом.
* Поддерживается загрузка Amiga MOD (4/6/8/N-канальные варианты:
  M.K./M!K!/M&K!/N.T., OCTA/OKTA/CD81/WOW!, xCHN, xxCH, xxCN, TDZx, FLTx,
  EXOx), включая старый 15-инструментный формат без тега — то есть
  практически всё, что можно найти на архивах трекерной музыки или
  вытащить из старых модов для Doom/ZDoom.
* Поддерживается Scream Tracker 3 (.s3m; несжатые PCM-сэмплы,
  Adlib/FM-инструменты и упакованные сэмплы пропускаются как пустые).
  Используются только включённые PCM-каналы: заглушённые (бит 7 в
  настройках канала) и Adlib-каналы (16-31) не конвертируются и не
  занимают одно из восьми мест DMM. Поддержаны команды A, T, C, D/K/L
  (слайды громкости), SCx, SDx, SEx, Bxx (переход назад в последнем
  паттерне становится точкой повтора) и флаг "быстрых слайдов
  громкости" ST3.00 (Dxy тогда двигается и на первом тике строки).
  Поддерживается также
  Impulse Tracker (.it), включая сжатые сэмплы IT214/IT215, режим с
  инструментами (клавиатурная таблица нота->сэмпл разрешается прямо при
  чтении), огибающие громкости, петли sustain, стерео-сэмплы.
* Сэмплы в формате ADPCM4 (редкая опция сжатия, встречающаяся в
  некоторых старых MOD/XM) декодируются корректно для 8-битных моно
  сэмплов — это единственный случай, где её вообще применяли на практике
  (в том числе и сам оригинальный тул поддерживал ADPCM4 только для
  такого случая).
* НЕ поддерживаются MOD-файлы, упакованные внешним ProPacker'ом (сигнатура
  "PPxx" в заголовке). Это не сокращение функциональности относительно
  оригинала: сам dmm2xm.exe тоже не умеет их распаковывать, а просто
  сразу же прерывает загрузку, как только видит эту сигнатуру — Grom PE
  никогда не реализовывал распаковку ProPacker. Такие файлы сначала
  нужно распаковать сторонним инструментом (например, UnPack в утилитах
  под Amiga/DOS), и уже потом конвертировать.
* В DMM нельзя выразить (и обратная конвертация игнорирует): портаменто
  и вибрато (E/F/G/H/U), арпеджио (J), панораму (у ноты DMM нет панорамы),
  фильтры и pitch-огибающие, NNA, каналовую и глобальную громкость
  (Mxx/Nxx/Vxx/Wxx), петлю паттерна (SBx/E6x). Переходы позиции Bxx
  (XM/MOD) отслеживаются: скорость/темп каждого паттерна берутся
  из реальных путей проигрывания (см. п. 1), а при включённой
  галочке "Разделить subsongs" каждый связный кусок становится
  отдельным .dmm. Не реализованы: номер строки при переходе
  на следующий паттерн (Cxx/Dxx: следующий паттерн всегда играется с
  первой строки; сам разрыв ряда Cxx порядок не меняет), старшее
  смещение семпла SAx (IT; обычное Oxx/9xx поддержано опцией
  вкладки 4).
* Громкость DMM имеет 127 ступеней, громкость XM — 64, поэтому при
  dmm -> xm -> dmm чётные значения возвращаются на единицу больше
  (60 -> 61). Частота дискретизации инструмента проходит через
  finetune XM (шаг 1/128 полутона), так что rate может сместиться на
  1-2 Гц. Оба эффекта неустранимы без отдельного канала хранения.

При построчной сверке с оригиналом также нашёлся реальный баг в
Pascal-коде: при чтении обычных (не-ADPCM) MOD-сэмплов после проверки
5-байтного тега "ADPCM" позиция чтения откатывается только на 4 байта
из 5 прочитанных, из-за чего каждый обычный сэмпл читался бы со сдвигом
на 1 байт и звучал бы "с шумом". В этом порте это исправлено.

Исправления и доработки обратной конвертации XM/MOD/S3M/IT → DMM
-------------------------------------------------------------------
(отличия этой версии от dmm2xm.dpr; часть багов есть в оригинале, и
обычная Python-версия повторяла их 1:1)

Время и порядок песни
1. Состояние speed/tempo берётся из порядка игры, а не хранения.
   Оригинал конвертирует паттерны подряд 0..N-1 с протекающим
   глобальным NewSpeed/NewTempo (dmm2xm.dpr, строки 839-844), хотя
   порядок игры (order table) обычно другой: интро/аутро лежат в
   конце, секции переиспользуются. Паттерн печётся со "скоростью",
   оставшейся от чужого, ранее лежащего паттерна. Пример —
   WFDEMO.S3M: порядок игры [0,1,3,2,4,5,7,10,11,6,6,8,9], а speed=12
   ставят паттерны 8 и 9, играющие ПОСЛЕ 10 и 11. Оригинал в порядке
   хранения доходит до 10–11 уже с протёкшим speed=12 и печёт их
   вдвое длиннее: 1024 тика вместо 507 (+7.8 сек на паттерн, молча;
   +16.8 сек на всю песню). Fixed-версия идёт по order table и печёт
   около 507 тиков (506,88 по формуле из п. 2).
   Если один паттерн переиспользуется в песне при разной скорости,
   DMM физически хранит лишь один вариант (один слот на индекс) —
   fixed оставляет первое вхождение и печатает предупреждение
   (пример: SWAMP2.mod, паттерн 0 при speed 6 и 3), оригинал молчал.

2. Точная формула тиков строки: speed*165/tempo с переносом дробного
   остатка (floor + накопитель) вместо Round(speed*166/tempo)
   оригинала (dmm2xm.dpr:590). Строка XM длится speed*2500/tempo мс,
   тик DMM принят за 1000/66 мс, отношение равно speed*165/tempo
   (165 = 2,5*66). Округление каждой строки отдельно накапливает
   ошибку ±0.5 тика на строку. Пример — SWAMP2.mod (speed 6,
   tempo 125: точно 7.92 тика/строку): оригинал печёт 8 на строку,
   fixed — в среднем 7.92 (253 против 256 тиков на паттерн, −141 тик
   / −2.1 сек на песню). Остаток тика переносится и между паттернами,
   а не теряется на границе, поэтому длина песни сходится с
   расчётной в пределах сотых долей секунды (проверено на IT/S3M/MOD).
   Константа 165 одна на оба направления (DMM_REF_TEMPO в
   dmm2xm_core.py): прямая конвертация создаёт XM с tempo 165 и
   speed = квантование, обратная делит на то же число — иначе
   dmm -> xm -> dmm сдвигал бы тайминг. XM, сделанные старой прямой
   конвертацией (tempo 166), читаются обратно на 0,6% короче.
   ВАЖНО: по исходному коду игры (SOUND.ASM) DOS-движок делает такт
   музыки каждые (sfreq >> 6) выходных сэмплов, то есть 64,10 тика/с
   при 11025 Гц (64,0–64,5 при других частотах звука), а не 66. В
   оригинальном DOS-движке песня идёт примерно на 3% медленнее, чем
   при 66 тиках/с (4:38 в трекере -> около 4:46 в игре). Если нужно
   совпадение именно с DOS-движком, поставьте DMM_REF_TEMPO = 160.

3. Эффекты, влияющие на время. Note cut (SCx): раньше каждый cut
   удлинял канал на x тиков, и каналы расходились друг с другом (до
   трети секунды на паттерн в реальных IT); теперь время сохраняется,
   а cut с x >= speed игнорируется, как в IT. Pattern delay (SEx в
   IT/S3M, EEx в XM/MOD) растягивает строку на нужное число повторов.
   Повторный запуск ноты (Qxy в S3M/IT, E9x в MOD/XM, Rxy в XM): нота
   заново "бьётся" каждые y тиков строки, при x != 0 с изменением
   громкости на каждом ударе (-1/-2/-4/-8/-16, x2/3, x1/2, +1..+16,
   x3/2, x2); Q00 повторяет предыдущее значение канала. В DMM это
   несколько нот подряд, новых инструментов не нужно. Интервал не
   короче строки (y >= speed) игнорируется. В режиме "Запекать" не
   применяется (нота там уже целиком нарисована в семпле).
   Команды Axx/Fxx: A00 в IT/S3M игнорируется (раньше становилась
   speed 1), слайды темпа T0x/T1x игнорируются (раньше превращались
   в tempo 32 навсегда). Bxx в последнем паттерне, ведущий назад,
   становится точкой повтора песни.

4. Точка повтора песни. Значение после маркера 255 в списке порядка
   DMM — индекс в списке порядка (движок: curseq = seq[i+1]), а не
   номер паттерна. Оба направления теперь работают с индексом: прямая
   конвертация переводит его в позицию порядка XM (учитывая паттерны,
   разрезанные из-за лимита строк), обратная берёт restart position
   XM.

Ноты, инструменты, громкость
5. Чтение заголовков инструментов XM по размерам из самого файла.
   Оригинал (BeRoXM.pas, LoadInstruments) читал расширенный
   заголовок как фиксированные 214 байт и заголовки сэмплов как
   фиксированные 40 байт, игнорируя поля isize и sample header
   size, — на файлах с нестандартными заголовками всё после
   первого такого инструмента читалось со сдвигом и превращалось
   в мусор. Здесь границы берутся из файла, с подстраховкой seek
   на объявленные позиции.

6. Имена инструментов всегда ≤8 символов: движок при поиске в WAD
   сравнивает только первые 8 байт имени, остальное молча
   отбрасывается. Схема: 6 символов из названия + 2-символьный
   суффикс слота в базе-36 (у оригинала был десятичный — ломался
   на 100+ инструментах); плюс проверка папки вывода, чтобы .DMI
   разных треков с одинаковым именем не перезаписывали друг друга.

7. Громкость из volume-колонки XM: валидный диапазон сырого байта
   0x10–0x50 (уровни 0–64). Старая проверка `<64` (как в dpr)
   роняла уровни 48–63 обратно в максимум 127; заодно верхний
   уровень clamp-ится в 127 вместо вылезавших 129.

8. Громкость и память канала (MOD/S3M/IT/XM). Нота с номером сэмпла и
   без явной громкости сбрасывает канал на громкость сэмпла
   (правило ProTracker/S3M), нота БЕЗ номера сэмпла и без громкости
   сохраняет текущую громкость канала (раньше играла на максимуме).
   Последний инструмент канала помнится и между паттернами (раньше
   нота без номера инструмента в начале следующего паттерна
   оказывалась тихой). Проверено на SWAMP2.mod.
   Номер инструмента БЕЗ ноты (S3M, MOD) сбрасывает громкость канала на
   громкость сэмпла, не перезапуская звук: так делают ритмичное
   "стробирование" (на чётных строках номер инструмента, на нечётных
   громкость 8). Раньше этот сброс терялся, и вместо пульсации звучал
   ровный тихий гул. Теперь он записывается событием громкости
   (для XM делается при загрузке: громкость по умолчанию плюс
   перезапуск огибающей; для IT такой сброс пока не разбирается).

9. Диапазон нот DMM — 0..95 (таблица частот игры из 96 значений; байт
   0xFE — пауза, 0xFF — событие громкости, а не нота). Ноты вне
   диапазона сворачиваются на целое число октав, чтобы не читать
   таблицу за её пределами.

10. Кодирование как в игровых данных: длинная нота — нота с delay=0
    (=256 тиков) и одна пауза на остаток (раньше нарезалось по 255 и
    паузы дробились по 256); пустой канал не добивается паузами до
    конца паттерна.

Сэмплы и особенности IT
11. Петли sustain используются (у DMM нет note-off, ноту всегда
    "держат", поэтому sustain-петля приоритетнее обычной). Ping-pong
    петли разворачиваются в прямые (если развёрнутый сэмпл влезает в
    65535 сэмплов, иначе остаётся прямая петля с предупреждением).
    Стерео-сэмплы сводятся в моно (раньше терялась половина данных и
    L/R чередовались). Сэмплы с C5Speed выше 65535 Гц прореживаются
    (раньше значение переполнялось и играло на две октавы ниже).
    16-битные данные при уменьшении до 8 бит округляются, а не
    усекаются. Каналы, заглушённые в трекере, не конвертируются.

12. Громкость внутри ноты — режимы вкладки 4 (см. выше). Внутри —
    траектория громкости звучащей ноты по слайдам Axy/5xy/6xy/EAx/EBx
    (MOD/XM), Dxy/Kxy/Lxy (S3M/IT), колонкам громкости XM и IT и
    установкам Cxx посреди ноты.

Ограничения движка игры
13. Движок ограничивает частоту воспроизведения каждой ноты диапазоном
    2000..65535 Гц (rate инструмента * множитель ноты, слишком высокие
    ноты быстрых сэмплов "слипаются" в одну частоту — тональность
    пропадает, слышен гул). Перед записью .DMI конвертер для каждого
    инструмента по реально сыгранным нотам подбирает максимальную
    безопасную частоту и сжимает PCM по времени в том же отношении:
    высота и длительность не меняются. Малые коэффициенты сжатия
    делаются линейной интерполяцией, от 2,5 — оконным sinc-фильтром
    (с подавлением алиасинга). Если диапазон нот одного инструмента слишком широк
    для одной частоты, в журнал выводится предупреждение (нужны
    отдельные копии инструмента).
    Побочный эффект: при dmm -> xm -> dmm у нескольких стоковых
    инструментов Doom2D (в оригинале их ноты тоже зажимались)
    .DMI получится слегка изменённым; ноты и тайминг при этом
    не меняются.

14. Проверки формата: не больше 65535 нот в песне (слово в заголовке),
    253 записей в списке порядка, 255 паттернов и 255 инструментов —
    раньше при превышении падало struct.error или данные молча
    обрезались, теперь понятная ошибка. Сэмплы длиннее 65535 сэмплов
    прореживаются, как и раньше.

Тишина на границе паттерна (VOLKI-B2.xm: инструмент обрывается ближе к концу паттерна)
--------------------------------------------------------------------------------------
По исходникам игры (SOUND.ASM, процедура playblk) движок обнуляет "звучащий голос" (irate) для
ВСЕХ 8 каналов КАЖДЫЙ РАЗ при переходе к новому паттерну в списке воспроизведения - даже если
для канала в новом паттерне вообще ничего не записано. В XM/IT/S3M/MOD нота, которую ничего не
остановило, просто продолжает звучать через границу паттерна; в DMM же она замолкает, если в
начале нового паттерна её не "переударить" явно. Раньше конвертер об этом не знал и просто
продолжал ноту паузой (0xFE) через границу - что в реальном движке даёт именно тот обрыв, который
слышно в VOLKI-B2.xm (паттерн 9→10, инструмент с петлёй, начатый под конец паттерна 9, обрывается
на границе, хотя в оригинале продолжает звучать).
Исправление: для каждого канала конвертер запоминает, какая ЗАЦИКЛЕННАЯ (не одноразовая - её
обрыв в конце данных сэмпла ожидаем и так) нота ещё звучит на конец паттерна, и если начало
следующего паттерна её не трогает, добавляет туда ту же ноту/инструмент/громкость - явный
"переудар", который восстанавливает обнулённый irate. Переудар звучит хвостом оригинала,
а не повторной атакой: часы огибающей сдвигаются на возраст ноты (RMS-среднее по
[age, age+hold] в режиме "Как раньше", хвост огибающей в событиях 0xFF и в запечённом
семпле), затухшая в тишину огибающая вообще ничего не переносит. Без этого BGM12.XM
на границе 33→33 давал залп полногромких атак (85 вместо 53-57) там, где в оригинале
тихо доигрывают хвосты.
Если один и тот же паттерн встречается в списке несколько раз с разным "хвостом"
предшественника (например, BGM12.XM: 30,33,33 — первая копия 33 доигрывает ноты
из 30, вторая уже ничего), копии с разным входным состоянием разводятся по
паттернам-дубликатам с новыми номерами (первый дубль оставляет родной индекс,
остальные дописываются в конец, список порядка перемаппируется; в журнал идёт
"extra pattern slot(s)"). Дубли различаются и по затухшему входному уровню,
поэтому тихий старый хвост и свежая нота не делят один слот.
Проверено (рендер DOS-точным плеером d2d_dmm_player2.py): в VOLKI-B2.xm граница паттернов 9→10
(каналы 4 и 6) теперь даёт правильный "переудар" той же нотой вместо обрыва. Такая же граница
без явного повтора нашлась и в СТОКОВЫХ песнях игры (АС, SUPER и другие) - то есть это реальный,
ранее неизвестный дефект, затрагивающий и оригинальную музыку Doom2D, а не только сторонние файлы.
В журнал выводится "Pattern-boundary continuity: re-triggered N note(s) ...".

Громкость новой ноты в XM без явной команды громкости (BGM16.XM: 97% нот звучали громче, чем надо)
--------------------------------------------------------------------------------------------------
У FastTracker 2 (и у MOD/S3M/IT, для которых это уже было учтено) новая нота без явной команды
громкости (колонка громкости, Cxx) звучит не на максимуме, а на СОБСТВЕННОЙ громкости инструмента
из заголовка сэмпла - многие инструменты специально настраивают её ниже максимума, чтобы не
проставлять Cxx на каждой ноте. Для XM-файлов конвертер этого не делал (в отличие от уже
исправленных MOD/S3M/IT) - каждая такая нота звучала на полной громкости. На BGM16.XM это
затронуло 97% всех нот (композитор почти везде полагался на громкость по умолчанию) -
самое заметное искажение звучания из всех, что нашлись в этом файле. Исправлено отдельным
проходом после загрузки XM (громкость по умолчанию инструмента известна только после того,
как загружены И паттерны, И инструменты - в разных версиях формата XM они хранятся в разном
порядке). На MOD/S3M/IT и на XM-файлах, где авторы явно проставляли громкость на каждой ноте
(как в VOLKI-B2.xm), это ничего не меняет.

Мультисемпловые XM-инструменты (sample_map)
-------------------------------------------
XM-инструмент может хранить несколько разных семплов и раскидывать ноты по ним через
карту клавиатуры (например, разные удары барабана на разных клавишах одного
инструмента) - а весь тракт конвертера, как и сам DMM, устроен проще: один инструмент
значит один семпл, и раньше всегда брался именно `sample[0]`, какая бы нота ни была
сыграна. BGM12.XM: инструмент 19 посылает ВСЕ ноты на второй семпл (19 КБ звука,
громкость по умолчанию 37), а нулевой у него пустой - в FastTracker2/OpenMPT инструмент
звучит нормально, а раньше конвертер брал пустой `sample[0]`, и все такие ноты
превращались в молчание. Инструмент 2 раскидывает ноты между ДВУМЯ семплами (26 нот
из 163 на первый, 137 на второй) - все 137 раньше играли чужим, первым тембром.
Исправлено на этапе загрузки XM (`_expand_xm_multisample_instruments`): если все
сыгранные ноты инструмента попадают в один (ненулевой) семпл, он просто переставляется
на место нулевого, номер инструмента не меняется (случай инструмента 19); если ноты
расходятся по нескольким семплам, первый использованный остаётся под тем же номером,
а под каждый следующий заводится новый номер инструмента - как уже делается для
IT-драм-китов (случай инструмента 2: 137 нот переходят на новый, 23-й инструмент).
Обычные, односемпловые инструменты (почти все) это не трогает.
Примечание: такое размножение номеров увеличивает счётчик инструментов -
проверка лимита 255 (п. 14) считает уже размноженные слоты.

Переходы Bxx в середине песни отслеживаются (BGM12.XM/BGM16.XM: длительности как в OpenMPT)
--------------------------------------------------------------------------------------
Раньше конвертер читал список воспроизведения (order list) построчно от начала до конца,
а Bxx использовал только в одном частном случае (переход назад в последней строке
последнего паттерна задавал точку повтора). Теперь Bxx отслеживаются везде:
* скорость/темп каждого паттерна берутся из реальных путей проигрывания
  (симуляция от начала, от каждого адреса перехода и от позиции после
  прыгающего паттерна — эффект Fxx внутри недостижимого куска не
  протекает в чужую песню; при конфликте побеждает самый ранний путь,
  о чём пишется предупреждение);
* галочка "Разделить subsongs" режет таблицу на связные песни
  по правилам самого OpenMPT: каждый ордер ровно в одной песне,
  песня обрывается перед чужим ордером, на замкнувшемся лупе
  (играется один раз) или в конце таблицы.
Проверено по openmpt123 --info/--subsong: BGM12.XM даёт 4 сабсонга
6:05 / 0:22 / 4:10 / 0:09 против 6:04 / 0:21 / 4:09 / 0:08 у OpenMPT
(сумма 10:44 сходится), BGM16.XM — 5 сабсонгов с совпадением до 0,1 с.
Без галочки весь список конвертируется в один DMM как есть (старая
модель), но уже с правильными скоростями.
Остаточное ограничение: байт повтора DMM указывает на одну позицию
порядка, поэтому песня без внутреннего лупа зацикливается
с собственного начала, а возврат в паттерн с другим звенящим
состоянием, чем линейный вход, передаётся приближённо.

Прямая конвертация DMM/WAD → XM
-------------------------------
Она работает по алгоритму оригинала; изменения продиктованы
обратным направлением и исходным кодом игры:
* XM создаётся с tempo 165 (DMM_REF_TEMPO) и speed = квантование;
* точка повтора переводится из индекса списка порядка DMM в позицию
  порядка XM (см. п. 4);
* нота DMM 0xFF (событие "только громкость", есть, например, в СОЛО)
  превращается в ячейку XM только с колонкой громкости, а не в
  ложную ноту, как было раньше;
* громкость DMM 1 больше не превращается в "стоп" (0x10 в колонке XM).
Проверка "туда и обратно" (dmm -> xm -> dmm) на 30 песнях doom2d.wad:
с квантованиями из таблицы первой вкладки все ноты попадают на те же
тики у 25 из 30 песен (до исправлений — у 0 из 30 из-за разных
констант 165/166 в двух направлениях). У остальных пяти (БОЖ_МУЗ,
ПРОБА, ТИШЬ, ТЫ_ПОБЕД, ВЗБУЧКА) задержки нот не кратны квантованию из
таблицы: с квантованием 1 совпадение по времени у всех 30. Ограничения
самого формата (64 против 127 ступеней громкости, +-1..2 Гц у rate,
разрезание паттернов длиннее лимита строк) описаны выше.

Упаковка в WAD и лимиты ресурсов
--------------------------------
По исходникам игры, все загруженные WAD-файлы делят один каталог на
MAX_WAD = 2000 записей (лампов); запись с уже существующим именем
только заменяет старую, а новое имя занимает слот. Стоковый doom2d.wad
уже использует 1468 записей (и имена DMI0001..DMI0091), свободно 532.
Песне нужен 1 лямп DMM плюс различные .DMI (одинаковые по содержимому
упаковщик DMM2WAD склеивает). Поэтому:
* в конце конвертации журнал пишет "WAD budget": сколько лампов нужно
  песне и сколько их свободно;
* .DMI новых песен нужно упаковывать с номером старта не меньше 92
  (DMM2WAD list.lst out.wad 92), иначе DMI0001.. заменят инструменты
  оригинальных песен;
* игра при загрузке песни держит в памяти все её инструменты сразу
  (у стоковых песен до 11 инструментов и ~130 КБ), поэтому режим
  "События громкости" предпочтительнее запекания.

Сообщения журнала обратной конвертации
--------------------------------------
* "Too many channels in module (N); using the 8 most prominent
  channels ..." — модуль шире 8 каналов, показано, какие выбраны.
* "Engine-rate compensation: time-compressed N DMI sample(s) ..." —
  для указанных инструментов понижена частота и сжат PCM, чтобы ноты
  укладывались в 2000..65535 Гц (п. 13).
* "Warning: post-compensation audit found N of M notes outside
  2000..65535 Hz ..." — после компенсации остались ноты вне диапазона
  движка (они будут звучать с неверной высотой).
* "Warning: ... instrument(s) span too wide a pitch range for one DMI
  rate" / "... cannot fit both their required rate and PCM data in one
  DMI" — инструмент нельзя уместить в один rate; нужны его копии.
* "Warning: sample ... exceeds the .DMI format's ... limits;
  downsampling" — сэмпл слишком длинный или быстрый, прореживается.
* "Warning: sample ... has a ping-pong loop too long to unroll" —
  ping-pong петля осталась прямой.
* "Warning: compensation reduced loop(s) to one PCM frame for
  instruments ..." — после сжатия петля инструмента стала короче
  одного отсчёта (слышен щелчок/гул вместо тона на самых высоких нотах).
* "Note: N extra pattern slot(s) for order repeats with different entry
  states ..." — повторы паттерна с разным звенящим состоянием разведены
  по дубликатам (pat X also as slot Y).
* "Warning: pattern N is reused later in the song at a different
  speed/tempo ... so the repeat will keep the first occurrence's speed"
  (и аналогичное про разные пути через Bxx) — один паттерн при разной
  скорости: DMM хранит один вариант, оставлен первый.
* "Note: the song uses position jumps (Bxx) ..." — в песне есть прыжки,
  скорости взяты из реальных путей (см. раздел про Bxx).
* "--- Subsong N/M: from XM order S, K orders, ... loops to ... / ends ..."
  и "Subsong split done: N DMM files sharing M distinct DMI ..." —
  отчёт о нарезке сабсонгов (см. пункт г вкладки 4).
* "Sample offsets (Oxx/9xx): N instrument copy(ies) ..." — сколько копий
  со сдвинутым стартом создано, сколько пропущено сверх лимита 32.
* "WAD budget: ..." — сколько лампов нужно песне (см. выше).
